System design vs software architecture

Lesson 0003 · System Design Fundamentals · Section 1 · ~5 min

Mission tie-in: Staff interviews live at the seam between these two. If you stay in "architecture" (how the code is layered) when asked a "system design" question (how photos reach 10M users with low latency), you've misread the question — a classic downlevel signal.

1. Scope, not quality

Software architectureSystem design
ScopeInside one application / serviceAcross applications, data stores, network, infrastructure
DecidesLayering, module boundaries, dependencies, patterns (MVC, hexagonal)Where data lives, how it's replicated/sharded, how the system scales and stays available globally
Optimises forMaintainability, testability, developer velocityScalability, availability, latency, consistency
Example questionHow is auth code structured? Which framework?How do we serve photos globally under 100 ms? Which store per data type?
Architecture is a subset of system design — the part that lives within a process boundary. Source: Educative GSD Fundamentals; Fowler, "Software Architecture Guide".

2. The seam: choices propagate both ways

  • Architecture → system design: choosing microservices creates system-design work — service discovery, an API gateway, inter-service transport, distributed tracing.
  • System design → architecture: a hard p99 latency budget pushes you toward a leaner internal design — fewer hops, in-process caching, no chatty ORMs.

"Should we use keyset pagination or offset pagination in this endpoint?" is primarily a question of…

Pagination strategy is an internal API/data-access design choice within a single service: architecture. It becomes a system-design concern only when it drives sharding or cross-service contracts.

3. Why the distinction earns points

Interview move When asked a design question, explicitly say: "I'll treat the internal service structure as an implementation detail and focus on the cross-system concerns — storage, replication, scale, failure." This signals you know which altitude the question is at.
Read this next (primary source): Martin Fowler — "Software Architecture Guide". ~12 min. Fowler's take on what "architecture" means and why the boundary is fuzzy but useful.

Recall

Which pairing is right?

Architecture is judged on how easy the code is to change and test; system design is judged on how the deployed system holds up at scale and under failure. They influence each other but grade differently.
